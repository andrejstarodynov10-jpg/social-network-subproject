# API временного бэкенда

Базовый адрес: `http://localhost:8000`. Интерактивная документация (можно пробовать запросы в браузере): `http://localhost:8000/docs`.

Бэкенд временный: данные хранятся в `backend/data/db.json`, картинки в `backend/uploads/`. На этапе 2 он будет заменён вашим.

## Общие правила

- Формат обмена: JSON. Исключение: создание и изменение новости отправляются как `multipart/form-data` (из-за картинки).
- **Сессии через cookie** `session_id` (httpOnly). Браузер сохраняет её сам после входа или регистрации. В `fetch` обязательно указывать `credentials: "include"`, иначе cookie не отправится.
- Открывайте фронтенд и обращайтесь к API через `localhost` (не `127.0.0.1`), иначе cookie не будет работать.
- Все запросы, кроме регистрации и входа, требуют входа. Без входа ответ `401`.
- Время: строки ISO 8601 в UTC, например `2026-11-25T10:00:00+00:00`.
- Картинки: в ответе приходит `image_url` вида `/uploads/abc.png`. Для `<img>` добавьте адрес бэкенда: `http://localhost:8000/uploads/abc.png`. Если картинки нет, `image_url` равен `null`.

### Ошибки

Ошибки бизнес-логики приходят в таком виде (код статуса в ответе HTTP):

```json
{ "detail": "Неверный логин или пароль" }
```

Ошибки валидации (код `422`) приходят в формате FastAPI, `detail` это список:

```json
{ "detail": [ { "loc": ["body", "password"], "msg": "String should have at least 8 characters", "type": "string_too_short" } ] }
```

| Код | Когда |
|---|---|
| 401 | нет входа или сессия истекла (7 суток), неверный логин или пароль |
| 403 | не хватает прав (чужой пост, действие только для админа) |
| 404 | запись не найдена |
| 409 | логин уже занят |
| 413 | картинка больше 5 МБ |
| 415 | недопустимый тип картинки (разрешены PNG, JPEG, GIF, WEBP) |
| 422 | данные не прошли валидацию |

## Тестовые аккаунты

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin12345` | администратор |
| `anna` | `user12345` | пользователь |
| `ivan` | `user12345` | пользователь |

Тестовые данные (посты, комментарии, 3 новости, 2 оповещения) создаются при первом запуске. Чтобы сбросить всё, остановите сервер и удалите папки `backend/data` и `backend/uploads`.

## Пример запроса из JavaScript

```js
const API = "http://localhost:8000";

const response = await fetch(`${API}/api/auth/login`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  credentials: "include",
  body: JSON.stringify({ username: "anna", password: "user12345" }),
});
const data = await response.json();
if (!response.ok) {
  console.log(data.detail); // текст ошибки
}
```

## Объекты

**Автор** (`author`)
```json
{ "id": 2, "username": "anna", "display_name": "Анна" }
```

**Пользователь**
```json
{ "id": 2, "username": "anna", "display_name": "Анна", "bio": "Люблю фотографию", "role": "user", "created_at": "2026-11-05T12:00:00+00:00" }
```
`role`: `"admin"` или `"user"`.

**Пост**
```json
{
  "id": 1, "text": "Всем привет!", "created_at": "2026-11-23T10:00:00+00:00",
  "author": { "id": 2, "username": "anna", "display_name": "Анна" },
  "likes_count": 2, "liked_by_me": false, "comments_count": 2
}
```

**Комментарий**
```json
{ "id": 1, "text": "Добро пожаловать!", "created_at": "2026-11-23T11:00:00+00:00", "author": { "id": 3, "username": "ivan", "display_name": "Иван" } }
```

**Новость**
```json
{
  "id": 1, "title": "Запуск социальной сети", "text": "Текст новости...", "category": "Обновления",
  "image_url": "/uploads/seed-news-1.png",
  "created_at": "2026-11-22T10:00:00+00:00", "updated_at": "2026-11-22T10:00:00+00:00",
  "author": { "id": 1, "username": "admin", "display_name": "Администратор" },
  "comments_count": 0
}
```

**Оповещение**
```json
{ "id": 1, "title": "Технические работы", "text": "Завтра с 03:00 до 04:00 сеть может быть недоступна.", "created_at": "2026-11-25T08:00:00+00:00", "author": { "id": 1, "username": "admin", "display_name": "Администратор" } }
```

## Авторизация

| Метод и адрес | Тело | Ответ |
|---|---|---|
| `POST /api/auth/register` | `{ "username", "password", "display_name"? }` | `201`, пользователь, сразу выставляется cookie (вход выполнен) |
| `POST /api/auth/login` | `{ "username", "password" }` | `200`, пользователь, выставляется cookie |
| `POST /api/auth/logout` | нет | `204`, cookie удаляется |
| `GET /api/auth/me` | нет | `200`, текущий пользователь (по нему можно проверить, вошёл ли пользователь) |

Правила регистрации: `username` 3-30 символов, только латинские буквы, цифры и `_`, регистр при проверке занятости не учитывается; `password` 8-128 символов; `display_name` до 50 символов (по умолчанию равно `username`).

## Профили

| Метод и адрес | Тело | Ответ |
|---|---|---|
| `GET /api/users/{id}` | нет | пользователь |
| `PATCH /api/users/me` | `{ "display_name"?, "bio"? }` (любое из полей) | обновлённый пользователь |
| `GET /api/users/{id}/posts?limit=20&offset=0` | нет | список постов пользователя, новые сверху |

`bio` до 300 символов.

## Посты, лайки, комментарии

| Метод и адрес | Тело | Ответ |
|---|---|---|
| `GET /api/posts?limit=20&offset=0` | нет | лента: список постов, новые сверху (`limit` 1-100) |
| `POST /api/posts` | `{ "text" }` (1-2000 символов) | `201`, пост |
| `DELETE /api/posts/{id}` | нет | `204`. Удалять может автор поста или админ |
| `POST /api/posts/{id}/like` | нет | пост с обновлёнными `likes_count` и `liked_by_me` |
| `DELETE /api/posts/{id}/like` | нет | то же, лайк снимается |
| `GET /api/posts/{id}/comments` | нет | список комментариев, старые сверху |
| `POST /api/posts/{id}/comments` | `{ "text" }` (1-1000 символов) | `201`, комментарий |
| `DELETE /api/comments/{id}` | нет | `204`. Удалять может автор комментария или админ |

Повторный лайк или повторное снятие лайка ошибки не вызывают.

## Новости

Читать могут все вошедшие пользователи, создавать, менять и удалять только админ (`403` для остальных).

| Метод и адрес | Тело | Ответ |
|---|---|---|
| `GET /api/news?category=&limit=20&offset=0` | нет | список новостей, новые сверху. `category` необязателен и фильтрует по точному названию |
| `GET /api/news/categories` | нет | список названий категорий, например `["Обновления", "Правила", "События"]` |
| `GET /api/news/{id}` | нет | новость |
| `POST /api/news` | `multipart/form-data`: `title`, `text`, `category`, `image` (файл, необязательно) | `201`, новость. Только админ |
| `PUT /api/news/{id}` | `multipart/form-data`: `title`, `text`, `category`, `image` (необязательно, заменяет картинку), `remove_image` (`true`, чтобы убрать картинку) | новость. Только админ |
| `DELETE /api/news/{id}` | нет | `204`. Удаляются также комментарии и картинка. Только админ |
| `GET /api/news/{id}/comments` | нет | список комментариев |
| `POST /api/news/{id}/comments` | `{ "text" }` | `201`, комментарий |

Ограничения: `title` до 150 символов, `text` до 20000, `category` до 50. Категория это просто строка, отдельного справочника нет.

Пример отправки новости с картинкой:

```js
const form = new FormData();
form.append("title", "Заголовок");
form.append("text", "Текст новости");
form.append("category", "События");
form.append("image", fileInput.files[0]); // можно не добавлять

await fetch(`${API}/api/news`, { method: "POST", credentials: "include", body: form });
// Content-Type вручную не указывайте: браузер сам поставит нужный
```

## Оповещения

Читают все вошедшие пользователи, создаёт и удаляет админ.

| Метод и адрес | Тело | Ответ |
|---|---|---|
| `GET /api/announcements` | нет | список оповещений, новые сверху |
| `POST /api/announcements` | `{ "title", "text" }` (заголовок до 120, текст до 2000) | `201`, оповещение. Только админ |
| `DELETE /api/announcements/{id}` | нет | `204`. Только админ |

## Допущения, которых нет в ТЗ

Это решения, принятые для упрощения. Если что-то не подходит, скажите, поправим:

- Все запросы кроме регистрации и входа требуют входа (чтение новостей и оповещений тоже).
- Категория новости это строка, а не отдельная сущность.
- Лайки есть только у постов (у новостей нет).
- Редактирование постов и комментариев не предусмотрено, только создание и удаление.
- Постраничность через `limit` и `offset`, общее число записей не возвращается.
